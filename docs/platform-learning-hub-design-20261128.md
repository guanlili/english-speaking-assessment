# 平台定位重构设计：从「口语平台 + 词汇模块」到「英语学习中心」

> 版本 2026-11-28 · 面向教师端 / 管理端 / 学生端的信息架构重设计
> 前提：平台不是口语产品，也不是单词产品，而是**综合英语学习平台**。口语课、单词课是并列的课程板块，未来还会有阅读课、听力课、写作课。

---

## 一、结论先行

1. **把「模块」升级为「课程板块（Course）」**：口语、词汇从"功能开关"变成一等公民的课程类型，有各自的工作台、内容库、任务体系和数据口径。
2. **导航从「平铺功能菜单」改成「三层结构」**：平台（学校）→ 课程板块 → 课堂与任务。侧边栏第一屏就是"我的课程"，而不是一堆工具入口。
3. **学生端首页从"口语练习入口"改成"学习中心首页"**：跨板块聚合今日任务、待复习、连续学习天数，口语和词汇同一个任务流里出现。
4. **教师端从"课堂管理"改成"课程工作台 + 教学任务中心"**：一个班在多个板块下都有任务，教师按板块切换工作台，但班级、名单、报告是共享底座。
5. **管理端从"功能授权开关"改成"课程包订阅与内容治理"**：授权页展示每所学校开通了哪些课程、到期时间、用量；内容库按板块分目录。
6. **不做大爆炸重构**：后端 `tenant_module` 模型已具备扩展性，一期只改 IA 与导航（前端路由 + 文案），二期再做跨板块聚合首页与统一任务中心。

---

## 二、现状诊断

| # | 现状 | 问题 |
|---|---|---|
| 1 | 侧边栏是平铺的 `Item[]`，靠 `module?: ModuleKey` 字段做显隐过滤（`filterItemsByModule`） | "模块"只表现为"某些菜单被隐藏"，用户感知不到课程体系 |
| 2 | 词汇入口散在 `vocab.$code.*`（学生）、`t.$code.vocab`（教师）、`/admin/vocabbooks`（管理） | 一个课程板块被拆成三段互不相识的入口，没有"词汇这件事的完整视图" |
| 3 | 学生首页 `home.$code` 以口语练习为主线 | 词汇任务只能靠独立路径进入，学生不知道"今天还有什么要学" |
| 4 | 教师端以"课堂"为唯一组织单位 | 没有"我教的这门课教到哪了"的板块视角；教师看不到跨板块的教学负载 |
| 5 | 授权页叫「模块授权 / module_key」 | 客户听到的是"功能开关"，卖不出"课程包"的价值感 |
| 6 | 内容库（题库、词库、单元、句型）按板块分散在不同管理页 | 校方管理员无法建立"我校有哪些课程资源"的整体认知 |

根因一句话：**平台的身份（英语学习中心）没有被建模，只是被"模块开关"临时拼出来。**

## 三、目标模型：三层信息架构

```
平台（学校）
└── 课程板块（Course，可扩展）
     ├── 口语课 speaking      → 课堂 · 任务 · 作答 · 报告
     ├── 单词课 vocabulary    → 词书 · 任务 · 复习 · PK/农场
     └── 阅读课 reading（未来） → 文章 · 任务 · 理解题 · 报告
          └── 共享底座：课堂（班级）、名单、教师、授权、数据看板
```

### 3.1 术语统一（对外文案口径）

| 内部概念 | 对外称呼（中） | 对外称呼（英） | 不再使用 |
|---|---|---|---|
| module / tenant_module | 课程板块 / 课程包 | Course | 模块、功能开关 |
| speaking | 口语课 | Speaking | 口语模块 |
| vocabulary | 单词课（词汇课） | Vocabulary | 单词模块 |
| reading（规划） | 阅读课 | Reading | — |
| classroom | 班级（课堂） | Class | 课堂（保留作口语场景词） |
| assignment | 学习任务 | Assignment | 作业 |
| learning hub | 学习中心 | Learning Hub | 首页、工作台 |

> 关键取舍：**"课堂"一词保留给"班级"这个组织单位**，课程板块一律叫"课"。这样教师说"我这周的课"指的是板块教学，学生说"我的班"指的是班级，语义不再打架。

### 3.2 课程板块注册表（从硬编码走向注册）

不做插件化框架，只做一张**声明式注册表**，新增板块时改一个文件 + 加路由：

| 字段 | 说明 | 口语 | 词汇 | 阅读（规划） |
|---|---|---|---|---|
| `key` | 板块标识，与 `tenant_module.module_key` 一致 | speaking | vocabulary | reading |
| `name` | 双语名 | 口语课 / Speaking | 单词课 / Vocabulary | 阅读课 / Reading |
| `icon` / `accent` | 视觉标识（同一图标体系，颜色区分） | 麦克风 / 蓝 | 书 / 橙 | 文章 / 绿 |
| `capabilities` | 该板块声明自己具备的能力 | 作答、评分、重录对比、跟读 | 认词、拼写、复习、PK | 阅读理解、定位题 |
| `studentRoutes` | 学生端入口清单 | 今日练习、我的成绩 | 今日任务、错词本、农场 | 今日阅读 |
| `teacherRoutes` | 教师工作台入口 | 班级看板、评阅、报告 | 词书、任务、正确率 | 文章、题目、报告 |
| `adminRoutes` | 管理与内容入口 | 题库、单元、句型 | 五级词库、授权台账、词书 | 文章库 |
| `entitlement` | 授权口径 | 按校开通 | 按校开通 | 按校开通 |
| `emptyState` | 未开通时学生/教师看到什么 | 咨询学校管理员 | 同 | 同 |

现在的 `useModules()` 已经能拿到 `["speaking","vocabulary"]` 与状态机（active / trial / expired），**注册表可以直接消费这份数据**，后端零改动即可支撑一期。

## 四、三端信息架构重设计

### 4.1 学生端：学习中心首页

**首页 = 今天学什么（跨板块一个流）**

```
┌ 早上好，测试学生A   🔥 连续学习 5 天
│
├ 今日学习（按板块分组，但混在一个待办流里）
│   ├ 口语课 · 复述练习《The Night Train》   未开始 · 约 8 分钟
│   ├ 单词课 · 词义+填空 10 词                已完成 8/10
│   └ 单词课 · 待复习 12 词（到期 3 个）      去复习
│
├ 我的课程（卡片式，只显示已开通）
│   ├ 口语课：上次 82 分 · 本周 3 次练习
│   ├ 单词课：已掌握 146 词 · 本班排名 6/24
│   └ （未开通的板块不出现，避免"灰掉的空卡"）
│
└ 学习档案（跨板块汇总，一眼看到"整体英语能力"）
    口语：流利度/准确度近 4 周趋势
    词汇：掌握量、复习到期、错词 Top10
```

导航（学生端左侧/底部）：

| 分组 | 入口 |
|---|---|
| 学习 | 学习中心（首页）、我的课程、今日任务 |
| 课程 | 口语课、单词课（开启后出现，未来加阅读课） |
| 成长 | 学习档案、成绩与报告、错题/错词本 |
| 我的 | 个人设置、帮助 |

**要点**：板块入口是"课程"，不是"功能"；未开通板块整块隐藏，不做置灰占位。

### 4.2 教师端：课程工作台 + 教学任务中心

```
导航
├ 教学
│  ├ 我的班级（名单、加入码、学生档案——共享底座）
│  ├ 教学任务中心（跨板块日历：本周要发什么、哪天截止、谁没交）
│  └ 课程工作台
│       ├ 口语工作台：班级看板、评阅、跟读对比、班级报告
│       └ 单词工作台：词书、任务、正确率、错词分布、PK/农场
├ 内容
│  ├ 我的内容（按板块分目录：口语题目/词书）
│  └ 内容复用（跨班复制、公共词库）
└ 数据
   ├ 班级报告（分板块 + 汇总）
   └ 学生档案（跨板块能力画像）
```

教师端的三条硬规则：

1. **班级是共享底座，课程是视图**：一个班不需要为"口语"和"单词"各建一次，班级只建一次，板块任务挂在同一个班上。
2. **工作台按板块切换，数据不跨板块混算**：口语分数和词汇正确率各自口径，只在"学生档案"里做并列展示，不做加权合成"英语总分"（避免口径不可解释）。
3. **发布任务统一入口**：教师从"教学任务中心"发起，先选板块再选题型，不要为了发词汇任务跳到另一个陌生页面。

### 4.3 管理端（校级 / 平台级）

```
校级管理员
├ 学校概览        本校开通课程、在用班级、活跃教师、本周任务量
├ 课程与授权      课程包列表（口语/单词/阅读）：状态、到期、用量、开通/续期
├ 内容治理
│  ├ 口语：题库、单元、句型库
│  └ 单词：词书、五级词库引用、授权台账
├ 成员与班级      教师账号、班级、名单
└ 数据            按板块用量 + 全校汇总（导出）

平台运营（跨校）
├ 学校管理（开校/停用）
├ 课程授权（跨校台账：谁开了什么、到期预警）
├ 内容中央库（五级词库、公共题库）
└ 平台大盘
```

**授权页的语义升级**：现在展示 `module_key / enabled / expires_at`；新页面按"课程包"展示：

| 课程包 | 状态 | 到期 | 本月用量 | 操作 |
|---|---|---|---|---|
| 口语课 | 使用中（manual，长期） | — | 1,284 次作答 | 续期 / 关闭 |
| 单词课 | 试用中（trial） | 2026-12-28（剩 30 天） | 320 次练习 | 转正式 / 关闭 |
| 阅读课 | 未开通 | — | — | 开通 |

状态机沿用现有 `active / trial / expired`（后端已实现），只改展示层与文案。

## 五、导航对照表（现状 → 目标）

| 端 | 现状入口 | 目标位置 | 处理 |
|---|---|---|---|
| 学生 | `home.$code`（口语练习首页） | 学习中心首页（跨板块待办） | 改造，保留路由 |
| 学生 | `vocab.$code.*`（词书/任务/PK/农场/错词） | 我的课程 → 单词课 | 归组，路由不变 |

## 六、跨板块聚合接口（二期）

学习中心首页需要一次请求拿到跨板块待办，建议新增只读聚合端点：

```
GET /api/v1/learning-hub/summary
→ {
    student: { streak_days, today: [ {course:"speaking", title, status, est_minutes, href},
                                     {course:"vocabulary", title, progress:{done, total}, href} ] },
    courses: [ {key, name, state, stats:{...}} ],
    profile: { speaking:{fluency_trend, accuracy_trend}, vocabulary:{mastered, due_today} }
  }
```

原则：

- **只读、按板块分别取数**，聚合层不做跨板块分数换算；
- 各板块 service 暴露 `summary_for_student(student_id)`，聚合端点只做编排，未来加阅读课 = 加一个 service；
- 单板块失败降级为卡片级"暂不可用"，不整页报错。

## 七、URL 与兼容策略

1. 现有路由全部保留（`/vocab/:code/*`、`/t/:code/*`、`/home/:code`），只新增分组壳与重定向，避免书签、老师培训材料、已发家长链接失效。
2. 新课程板块统一前缀 `/course/:courseKey/...`（可选，二期），旧路径 301 到新路径。
3. 板块隐藏逻辑不变（未开通不出现），但从"菜单少几项"改为"课程卡不出现 + 直接访问给出统一未开通页"（复用现有 `ModuleDeniedPanel`）。

## 八、分期落地

| 期 | 范围 | 改动面 | 预估 |
|---|---|---|---|
| **P0 一期（1 周内可交付）** | 课程注册表 + 侧边栏分组重构 + 文案统一（模块→课程）+ 三端菜单按板块归组 | 纯前端 + 1 个注册表文件；后端 0 改动 | 3–4 人日 |
| **P1 二期** | 学习中心首页（跨板块待办）+ 教师教学任务中心 + 学生跨板块学习档案 | 新增聚合端点 1 个、页面 3 个；各板块 service 加 summary 方法 | 8–10 人日 |
| **P2 三期** | 课程与授权统一页 + 内容治理按板块目录 + 阅读课接入验证（用注册表新增第三个板块做压力测试） | 管理端改造 + 新板块接入 | 6–8 人日 |

验收标准（一期即可验）：

- 新用户登录后，一眼能说出"这个平台有口语课和单词课"，而不是"有一些功能"；
- 任一板块的入口，在三个端都能找到且位置对称（学生"我的课程"、教师"课程工作台"、管理"课程与授权"）；
- 关闭某校单词课后，三端相关入口同步消失，且直接访问给出统一提示。

## 九、需要拍板的四个决策点

1. **品牌与定位文案**：首页主标题用"英语学习中心"还是"XX 英语学堂"？对外材料需统一一次（招生页、家长端宣传口径）。
2. **是否做"英语总分"**：建议不做跨板块合成分，只做并列展示；若要做，必须先定义权重与口径，否则不可解释。
3. **课程板块的授权粒度**：现在整校一行（`tenant_module`）。未来阅读课是否可能出现"按年级/按班开通"？若可能，模型要预留 `scope` 字段，一期不动。
4. **教师是否跨板块共用班级**：建议共用（同一班同一批学生），避免"单词班/口语班"两套名单，这决定了任务中心的数据模型。

---

## 附：一句话总结

**平台的身份不是"口语 + 词汇"，而是"课程体系"。把板块建模成课程、把三端导航按课程对称摆放、把首页变成跨课程的学习中心，剩下的事都能按板块增量接进来。**
