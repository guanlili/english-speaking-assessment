# 词汇第三批：课堂 PK 与专注农场——前置设计（2026-11-22）

> 状态：待产品确认项已单列；实现按本文件「已定案」部分推进。
> 约束：班内、自愿、不跨校公开；PK 不替代教师任务首答统计与发布快照；农场不新造并行积分。

## 1. 实时通道选型与容量目标（可验收）

### 1.1 现状事实

| 项 | 现状 |
| --- | --- |
| 传输 | 全站纯 REST；代码中无 WebSocket / SSE / 长连接 |
| 部署 | 单后端容器，`WORKERS=1`（`.env`），无 Redis / 消息中间件 |
| 数据库 | PostgreSQL（psycopg3），现有业务均为同步 Session |
| 入口 | 前端 nginx 把 `/api` 反代到后端（`frontend/nginx.conf`） |

### 1.2 选型

**选定：SSE（Server-Sent Events）+ 数据库状态 + HTTP 轮询降级。**

- 服务端只推送「状态有变化」的通知与快照版本号，比赛状态以 DB 为准；SSE 不承担计分与判分。
- 前端用 `fetch` 读取 `text/event-stream`（可带 `Authorization` 头），不用 `EventSource`（它无法设请求头，避免把 token 放进 URL/日志）。
- 响应头 `X-Accel-Buffering: no`，避免 nginx 缓冲导致推送滞留；单连接最长 5 分钟，到期客户端自动重连。
- 降级路径：SSE 建连失败 / 断流 / 服务端不支持 → 自动切 1.5 秒轮询；轮询与 SSE 读同一套快照接口，行为一致。
- 多 worker 约束：单 worker 为首批容量前提；若未来 `WORKERS>1`，本方案自动以轮询为准（不依赖进程内广播、不要求粘性会话），SSE 仅作为单 worker 优化。不引入 Redis/消息队列。

**未选方案与理由**：WebSocket 需新增协议与心跳治理、nginx 升级配置，收益主要是双向低延迟，而本玩法作答本身是 HTTP 请求；轮询单独使用在 20 人 1v1 下延迟与请求量可接受，但观感与服务器压力不如 SSE 平滑，故保留为降级而非主方案。

### 1.3 单班容量目标（验收口径）

| 指标 | 目标 | 验证方式 |
| --- | --- | --- |
| 单班规模 | 40 名学生 | 课堂名单上限沿用现有 40 人假设 |
| 同时在线 PK 玩家 | 20 人（10 场 1v1） | 容量探针并发 20 客户端 |
| SSE 并发连接 | 40 条（20 玩家 + 20 观战/等待） | 探针建连并保持 60 秒 |
| 状态传播延迟 | P95 ≤ 1.5 秒（服务端状态变更→客户端可见） | 探针记录时间戳差值 |
| 作答接口延迟 | 本机参考环境 P95 ≤ 300 ms | 探针统计 `/answers` |
| 答案正确性 | 重复提交/断线重发 0 丢分、0 重复计分 | 幂等键 + 唯一索引测试 |
| 断线恢复 | 重连后 1 个状态周期内回到当前题与剩余时间 | 断线用例 + 浏览器演示 |

容量探针作为仓库脚本（`backend/scripts/pk_capacity_probe.py`）交付，结果写入 #517 证据；不以「理论可支撑」代替实测。

### 1.4 异常与降级规则

| 场景 | 行为 |
| --- | --- |
| SSE 断流 | 客户端切轮询；比赛不暂停，服务端时钟继续 |
| 后端重启 | 客户端重连并按 `match_id` 恢复；已入库答案不回滚 |
| DB 瞬时不可用 | 客户端显示「连接中断，正在重试」，不判分、不结算；恢复后按 DB 状态继续 |
| 重复提交 | 同 `idempotency_key` 返回首次结果，不二次计分 |
| 超时 | 服务端按截止时间结算，未答题记 0；结算幂等 |

## 2. 榜单 / 对战底线（已定案）

1. **班内**：PK 大厅、匹配、比分只对「本课堂成员 + 本课堂教师」可见；不出现跨班/跨校榜单。
2. **自愿参与**：学生必须显式点击「加入 PK」；不自动拉人、不因未参与扣分或影响任务完成度。
3. **不公开**：不生成全校/全站排行，不对外分享战绩；教师端仅在课堂内看到本轮参与与比分。
4. **不替代教师任务**：PK 使用独立表（大厅/对局/作答），**不写 `VocabularyAnswer`、不改任务首答统计、不动任何发布快照**；教师结果页不混入 PK 数据。
5. **口径分离**：PK 判分仅用于本局胜负；练习正确率、完成率、测验有效成绩仍按既有口径。

## 3. PK 最小闭环（先做）

- 教师在本班开一个 PK 大厅（选词库/题量/单题限时），学生在词汇首页自愿加入；满 2 人即可配对，1v1，最多 20 人同时排队（10 场）。
- 服务端统一生成题单（同一局同序），题面复用词汇四题型与快照内容；倒计时以服务端时间为准。
- 作答走独立接口：服务端判分、幂等键、首答一次有效；正确 +100，速度奖励 0–50；错答 0。
- 结算：双方完成或到时；总分高者胜，同分比总用时；结果仅本局可见，可再来一局。
- 断线重连：按 `match_id` 恢复当前题、剩余时间与比分；超时由服务端结算。

## 4. 农场最小闭环与既有激励边界（先做）

| 维度 | 定案 |
| --- | --- |
| 成长事件 | 只认真实「有效练习事件」：任务练习 / 自主练习 / FSRS 复习的**首答**；测验不计；切屏、空闲不产生成长，也不宣称能证明专注 |
| 成长状态 | 每账号一块地（跨班连续），4 个阶段，阈值 0 / 5 / 12 / 20 点；每 1 个有效首答 +1 点，每日最多计 30 点 |
| 收获 | 成熟后可收获，获得 **10 XP**；每日农场 XP 上限 10，防止刷分 |
| XP | 写入既有 `student.xp`（与口语每日计划同一余额、同一账），不新造货币、不单独排行 |
| streak | **不新增口径**：仅既有每日计划结算推进；农场不推进、不重置 streak |
| badge | 使用既有 `student_badge` 账本，新增农场徽章 key（首次收获 / 累计收获 7 次）；不建第二套徽章表 |
| 展示 | 农场页显示成长阶段、今日有效练习数、XP 余额、streak 与徽章（只读，来源标明）；收获结果留痕 |
| 可保存 | 农场状态落库，刷新/换设备/换班保持 |

**不做**：并行积分、独立等级、独立排行榜、用停留时长推断专注、把农场奖励计入教师任务统计。

## 5. 待产品确认（不自行改范围）

1. 实时基建是否上云（多实例/Redis/托管消息服务）：当前方案单 worker + DB 状态，单班 40 人可验收；若要求多班同时大并发，需确认云资源与预算。
2. 农场玩法取舍：一块地四阶段 vs 多地块/作物选择；收获 10 XP/日上限 10 是否合适；徽章是否进入教师可见面板。
3. PK 首个赛制确认：1v1 淘汰/积分、题量 8 题、单题 20 秒、速度奖励 0–50 的数值是否作为首版口径。
4. 是否允许教师手动开 PK（当前设计为教师开大厅），以及是否需要 PK 结果进入课堂看板。

以上四项在实现中按「可演示默认值」落地，均可在 #517 后续评论中调整；未确认前不扩大范围。
