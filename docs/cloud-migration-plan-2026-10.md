# 云资源迁移方案：个人账号 → 公司名下（全火山引擎）

> 日期：2026-10-29 ｜ 状态：待执行
> 结论：平台正式商用前，把目前挂在个人名下的全部云资源迁到公司主体，并统一收敛到火山引擎一个企业账号。全流程用户无感知，唯一长周期环节是 ICP 备案（约 1-4 周），须最先启动。

## 一、背景

1. 平台（BRS English Learning Platform）目前的生产资源全部在个人账号下：腾讯云服务器、域名、DNS、火山方舟 AI 密钥。正式给客户交付后，资源和费用必须归公司主体。
2. 已拍板：公司统一使用火山引擎。AI 服务（语音识别、评分、配音）本来就在火山，整站收敛后一个账号、一张账单。
3. 部署形态不变：单机 Docker Compose（数据库 + 后端 + Nginx + 证书容器，见 `compose.yml`）。迁移是"换房子"，系统本身不动。

## 三、公司侧采购清单（火山引擎一站式）

按办理顺序排列；第 1 项是其余所有项的前置。

1. **火山引擎企业账号注册 + 企业实名认证**（需要营业执照）。
2. **云服务器 ECS ×1**：通用型 g4i，4核/16G，北京地域；云盘 260G 单盘；带宽按流量计费、峰值 100M；**包年包月**（备案需用该实例生成备案服务码，按量实例不能用于备案）。
3. **ICP 备案**：公司主体 + 火山接入。因主体和接入商都变，实际是在火山提交新备案；与旧个人备案（腾讯接入）的衔接方式，开工前打火山备案客服确认一次。
4. **域名**：转入火山，或留在原注册商但过户到公司名下；DNS 解析迁到火山云解析。
5. **对象存储 TOS 桶 ×2**：一个做每日备份的异地副本（补上"备份只在本机"的短板），一个做迁移中转。私读写。
6. **方舟大模型 + vei AI 网关**：与服务器同一账号，生成两套密钥——方舟 API Key（语音识别 + 开放题评分）与 vei 网关 Key（标准音合成）。新账号需在控制台开通豆包模型权限；模型调用名必须用带日期后缀的快照名。
7. **证书自动续期适配（小改造）**：证书签发的 DNS 校验从 DNSPod 密钥改为火山 DNS 插件（acme.sh 较新版本内置 `dns_volc`，部署时确认版本）；兜底方案为改 HTTP-01 校验或火山免费证书。Nginx 配置结构不变。
8. **SMTP 企业邮箱凭据**：火山无邮件服务，用任意厂商企业邮箱；补上告警邮件与密码重置邮件链路。
9. （可选）**Sentry 账号**：前后端错误监控，免费档够用，决定用再开。

## 四、迁移步骤与关键顺序

**备案顺序是锁死的，不能乱**：备案通过前域名不得解析到火山服务器（接入商会拦截未备案）；全程保持旧个人备案有效，直至新备案通过后才能切换，最后再注销/变更旧备案。中途注销旧备案会造成域名两边都打不开。

1. **第 0 天**：注册火山企业账号并实名；购买包月 ECS；创建 TOS 桶；启动域名过户与备案申请。
2. **备案期间并行**：公司账号开通方舟模型、生成两套新密钥；在现有生产机执行一次完整备份并上传 TOS，验证备份可读。
3. **备案通过后切换**：
   - GitHub Secrets 更新：`SERVER_HOST` 指向新 ECS，替换 `ARK_API_KEY`、`ARK_TTS_API_KEY`、DNS 密钥等；
   - 流水线在新机全新部署（全自动，约 9 分钟）；
   - 备份包经 TOS 恢复数据（流程见 `docs/backup-restore.md`，恢复后按演练清单验证：就绪检查、教师/学生登录、课堂与历史成绩、录音回放）；
   - 切 DNS 前把解析 TTL 降至 60 秒（提前 1-2 天）；停机窗口为数据恢复时长，量级小时级，约在无课时段执行。
4. **双跑观察 1-2 周**：老腾讯机保留不动作回退保险。
5. **退役个人侧**：注销/变更旧备案 → 个人腾讯云服务器退订 → 个人火山密钥停用。

## 六、风险与回退

1. **切换回退**：DNS 切回老机即可（TTL 已调低，生效分钟级）；老机保留 1-2 周。
2. **数据一致**：切换窗口内停止新作答，切换前最后一次备份为恢复基准；恢复后按 `docs/backup-restore.md` 清单人工验证业务功能，校验和通过不等于业务恢复。
3. **备案空窗**：见第四节加粗说明，严格按顺序执行。
