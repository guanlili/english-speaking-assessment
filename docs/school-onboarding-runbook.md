# 新学校接入操作手册（第二校及以后）

> 面向「给已经在跑的部署加一所学校」这件事。一条命令或一个页面开校，之后全部在学校管理员
> 自己的后台里完成，平台侧不需要再动手。
> 设计与权限依据见 [multi-tenant-design.md](multi-tenant-design.md) §3/§4；
> 备份与恢复见 [backup-restore.md](backup-restore.md)。

## 两条入口，选一条

| 入口 | 谁用 | 怎么做 |
|---|---|---|
| **A. 平台运营后台**（推荐） | 手边有平台运营账号 | 登录后进「学校管理」→「开新学校」 |
| **B. 服务器脚本** | 没有平台账号、或要自动化 | 部署目录下跑 `backend/scripts/onboard_tenant.sh` |

两条路效果相同：都在 `tenant` 表建一条 `status=active` 的租户。区别是 B 会顺手把学校管理员
建出来并把初始密码打印在终端（只打印一次）；A 只建学校，管理员要在学校管理页另行添加。

## 前置条件

- 服务在跑：`curl -fsS https://<你的域名>/api/v1/utils/health-check/` 返回 `true`
- 数据库可连（脚本走 `docker compose -f compose.yml exec -T db`，需在生产部署目录执行）
- 想好 **slug**：小写字母/数字/连字符，2–31 位。它进 URL，建成后不要改——学生登录链接
  是 `/s/<slug>/login`，改了链接就全失效
- 想好 **管理员邮箱**：这个人将成为该校 `school_admin`，之后所有建号由他做

## Step 1 · 开校

### A. 平台运营后台

「学校管理」页 →「开新学校」，填学校名与 slug。停用学校时入口直接 404（挡新登录），
学校与数据永不物理删除；默认学校是租户锚点，不允许停用。

### B. 服务器脚本

```bash
cd <部署目录>
bash backend/scripts/onboard_tenant.sh bj-2zhong "北京第二中学" admin@bj-2zhong.edu.cn
```

- 第三个参数省略时默认 `admin@<slug>.edu.cn`
- **幂等**：租户已存在则只更新校名；管理员已存在则跳过建号、**不重置密码**
- 管理员密码只打印这一次，转交后请其首登改密（`/change-password`）
- 输出末尾会给出登录入口 `https://<域名>/s/<slug>/login`

## Step 2 · 建教师

学校管理员登录 `/s/<slug>/login`（教师与管理员都走这个入口，账号填邮箱）→「教师管理」→
「新建教师」。建号自动落本校；停用即挡登录但数据保留；教师忘密由管理员在此重置。

学生账号**不在这里建**，走 Step 4。

## Step 3 · 建课堂（拿课堂码）

教师登录后「我的课堂」→「新建课堂」。创建成功会给出**课堂码**（如 `BJ201X`），
这个码发给学生，配合学号使用。同一个老师带几个班就建几个课堂。

## Step 4 · 导入学生

课堂内「导入学生」，每行一条：

```
20260101 张三
20260102 李四
```

- 学号 + 姓名，空格或制表符分隔
- 新学号自动建号，**初始密码统一为 `brs123456`**，首登后学生自行修改
- 学号已存在于别的班的：姓名一致即视为同一学生，加入本班且**不重置密码**；
  姓名不一致会拒绝该行——先核对名单再导入
- 与历史匿名练习数据同名的会自动绑定，学生的历史 XP 和作答不会丢

## Step 5 · 备内容

内容库按学校隔离，教师自己就能建：文章（朗读素材）、复述句、场景问答、题库。
平台侧预置的内容同样只对所属学校可见。

> 教师端左侧「题目库」（`/create`）按题型分几个分区，底层页面分别是
> `/admin/passages`、`/admin/scenarios`、`/admin/questions`——这几个路径对教师角色开放，
> 不需要平台账号。菜单里的「平台大盘」「用户」「课堂管理」等才是平台运营专属。

## Step 6 · 发布练习

课堂面板（`/t/<课堂码>`）选内容 → 预览 →「确认发布到课堂」。发布后：

- 全班学生当天看到同一份练习（快照 + 指派镜像同时写入，学生中途改库里的题不影响已发布内容）
- 面板页头显示「已提交 x/y」，右侧「学生当前练习」会写明题型构成，如
  「按题指派 · 1 篇朗读 · 1 句复述 · 2 道问答」

## Step 7 · 冒烟自检（上线当天做这一遍）

**1）学生侧**：用 `https://<域名>/s/<slug>/login` + 一个真实学号 + `brs123456` 登录，
做一道朗读和一道问答，确认能录音、能提交、能看到分数。

**2）教师侧**：刷新课堂面板，确认该学生计入「已提交」，名单行有分数。

**3）接口侧**（可选，用于留证）：

```bash
TOKEN=$(curl -s -X POST "https://<域名>/api/v1/login/access-token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=<教师邮箱>&password=<密码>" | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')

curl -s -H "Authorization: Bearer $TOKEN" \
  "https://<域名>/api/v1/classes/<课堂码>/board" \
  | python3 -c 'import sys,json;d=json.load(sys.stdin);print(d["submitted_count"],"/",d.get("class_size"))'
```

**4）隔离自检**：用另一所学校的教师账号请求上面这个课堂码，应当拿不到数据（RLS + 租户守卫）。

## 常见操作速查

| 要做的事 | 去哪 |
|---|---|
| 教师忘密码 / 离职 | 学校管理员 →「教师管理」→ 重置密码 / 停用 |
| 学生忘密码 | 教师在学生名单里点「重置密码」（也支持批量重置为默认密码 `brs123456`） |
| 停用整所学校 | 平台运营 →「学校管理」→ 停用（挡新登录，数据保留） |
| 改校名 | 学校管理页改；脚本重跑也只会更新校名 |
| 学生转班 | 在目标课堂重新导入该学号（姓名一致即并入，不重置密码） |

## 出错与清理

- **开校失败**：脚本报 slug 不规范就改 slug 重跑；报数据库连不上先查 `docker compose ps`。
  `set -euo pipefail`，中途失败不会留下半条记录（租户 upsert 与建号是两条独立语句，
  第二条失败时租户已在，重跑即可补齐，因为建号本身也有存在性判断）。
- **测试学校要清掉**：平台没有物理删除入口，这是有意的（数据永不物理删除）。
  确需清掉测试学校时，先按 `docs/backup-restore.md` 导一份 `pg_dump` 留底，再在库里按
  `tenant_id` 清理；顺序是先业务表、后 `user`、最后 `tenant`，且必须确认没有任何学校的
  `current_exercise_id` / 会话还挂在它上面。
- **学生登不进**：先确认他用的入口带 slug（`/s/<slug>/login` 而不是根路径 `/login`，
  后者是通用登录，未带学校上下文）；再确认学号属于这所学校。

## 为什么脚本没有图形界面

`onboard_tenant.sh` 是 D 期「学校自助开通」之前的种子工具，平台运营后台的「开新学校」
是它的图形等价物。两处逻辑要一起改：脚本改 `tenant` 与 `user` 表，后台走
`admin_tenants` 路由。新增字段时不要只改一边。
