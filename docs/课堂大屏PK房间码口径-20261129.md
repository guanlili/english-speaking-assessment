# 课堂大屏 PK（房间码形态）口径 · 20261129

对应 issue #619。手册 §06 的「教师大屏一键开赛」形态，与既有 1v1 排队 PK 并存。

## 一、两种 PK 的边界

| | 1v1 排队 PK（2026-11-22 版） | 大屏 PK（本版） |
| --- | --- | --- |
| 入口 | 学生点「加入 PK」自动配对 | 教师开房 → 6 位码，学生凭码入场 |
| 对局规模 | 1v1，同班最多 10 场并发 | 全班同场，单房上限 60 人 |
| 题序 | 两人各自推进 | 全班同一题序、同一倒计时 |
| 计分 | 单场比分，胜负结算 | 个人累计分；team 赛制另有队伍总分 |
| 数据表 | `vocab_pk_lobby/match/player/answer` | `vocab_pk_room/room_player/room_answer` |

两套互不读写：同一堂课可以先后开两种，互不影响。

## 二、房间生命周期

1. **开房**（教师，`POST /classes/{code}/vocabulary/room`）：选词库、题量（1–20）、单题秒数（1–60）、赛制（`solo`/`team`）与小组数（2–6）。开房即固化题单，之后改词库不影响本轮。
2. **房间码**：6 位数字，全局唯一、不回收（避免旧码误入新房间）。同一课堂同时只有一间等待中/进行中的房；再开房会把旧房置为结束。
3. **入场**（学生，`POST .../room/join`）：凭码入场；`team` 赛制按入场顺序均分到 1..N 组，`solo` 个人计分。重复入场幂等。
4. **开赛**（教师，`POST .../{room_id}/start`）：记录服务端开始时间，题序从 0 起。
5. **推进**：无后台任务。当前题 = `floor((now - started_at) / 单题秒数)`，剩余秒 = 单题秒数 − 已过余数；跑满题量即视为结束并落库 `ended`。
6. **结束**（教师，`POST .../{room_id}/end`）：提前收口，已答保留。

## 三、作答与计分

- 只接受**当前题序**的提交：题序不匹配或已翻页 → 409，前端提示「等下一题」。
- 判分复用既有题型口径（选择类比对选项词条，其余按拼写/词根拼装）。
- 得分 = 答对 100 分 + 速度奖 0–50（按提交时剩余时间比例）。答错 0 分。
- 幂等：同一人同题只计首次提交，重放返回首次结果，不二次计分。
- 断线重连：客户端 1 秒轮询 `me` 快照，服务端时间权威，回来即当前题。

## 四、主持端大屏（`GET .../{room_id}/board`）

- 显示当前题号/倒计时、本题作答人数与正确率、个人排名（同分比总用时）、队伍积分。
- 词形（headword）只在**翻页之后**揭晓，未翻页不下发，避免大屏提前泄题；`en_zh` 题面本身就是单词，作答前可见（与 1v1 PK 同口径）。
- 结算：队伍/个人排名 + 逐题正确率 + 易错词清单。

## 五、口径隔离（沿用设计稿 §2，不因房间形态改变）

- 只写 `vocab_pk_room_answer`：不写 `VocabularyAnswer`、不改任务首答成绩与完成率、不写错词本、不进 FSRS。
- 手册要求的「PK 错词回流」**不做**（#619 口径定稿已固化）：课堂互动数据不进学情统计，避免污染教师任务口径。
- 跨班访问一律 404；学生只能读自己所在房间的 `me` 视图，主持端仅本班教师可读。

## 六、容量与已知未做

- 单房 60 人上限，主持端 1.5 秒轮询、学生端 1 秒轮询，无 SSE/Redis。
- 40 人同场容量探针（P95）尚未实测；主持端大屏在 1920 宽下按两栏布局，390/820/1180 三档随卡片自适应。
- 未做：跨班联赛、赛季、Kahoot 导入、教室公用平板模式。
