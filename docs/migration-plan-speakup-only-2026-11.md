## 三、新机规格建议

现状实测：4 核但 **内存只用了 2G/15G**（DB 86.8M、评分走远端 API、不在本机跑模型）。所以不必照抄 4C16G：

| 方案 | 规格 | 适用 | 备注 |
| --- | --- | --- | --- |
| **推荐** | 4C / 8G / 200G 系统盘 | 试点 + 初期商用 | 留 100G 给音频（180 天 TTL 稳态约 1.7G，充裕）+ 备份 14 天 |
| 保守 | 4C / 16G / 260G | 若预期并发评分翻几倍 | 与原机同规格，迁移时少一个变量 |
| **实际购买**（2026-11-19） | **8C / 32G / 500G 极速型SSD PL0** | 已开通，超上两档 | `ecs.g4i.2xlarge`，首月 55 折后实例 ¥492.80 + 盘 ¥137.50 ≈ **¥630/月**；只买了 1 个月，后续可降配回调推荐档 |

**2026-11-19 新机实测信息**：公网 IP `115.190.122.24`，Ubuntu 26.04 LTS，BGP 按流量后付费（峰值 100M）。SSH 已收口：两台开发机各一把独立密钥已入 `authorized_keys`（下单 pem 留作冷备）；**密码登录已关死**——火山 Ubuntu 默认 `PasswordAuthentication yes`（公网 root 爆破面），且 sshd 配置「先到先得」，须改 `/etc/ssh/sshd_config:78` 与 `50-cloud-init.conf` 两处源头，只在 `sshd_config.d` 里加 `99-` 文件**不生效**。

必须项：**包年包月**（备案要用该实例生成服务码，按量实例不行）、北京地域（与现有用户群体和备案一致）、带宽按流量计费（试点日活低，按带宽不划算）。

## 四、Secret 替换表（27 项里真正要动的）

| Secret | 是否要换 | 换成 |
| --- | --- | --- |
| `SERVER_HOST` | ✅ | 新 ECS 公网 IP / 域名 |
| `SERVER_SSH_KEY` | ✅ | 新机部署公钥（建议新生成一对，不复用老机密钥） |
| `DEPLOY_PATH` | 可选 | 默认 `/opt/speakup`，新机可沿用 |
| `ARK_API_KEY` / `ARK_TTS_API_KEY` / `VOLC_ASR_API_KEY` | ✅ | 公司火山账号重新生成；`ARK_ASR_MODEL` / `ARK_RUBRIC_MODEL` 用带日期快照名 |
| `DP_ID` / `DP_Key` | ✅ | 换成火山 DNS 的 AK/SK（**证书续期专用，与解析操作分离**） |
| `TLS_DOMAIN` / `FRONTEND_HOST` | 视域名策略 | 若域名不变则值不变；域名过户完成前先别改 |
| `POSTGRES_*` / `APP_POSTGRES_*` / `PLATFORM_POSTGRES_*` | 建议换 | 新机新库，顺手轮换一次密码 |
| `SECRET_KEY` | 建议换 | **会导致已签发 token 全部失效**（用户需重新登录），选在停机窗口内换 |
| `FIRST_SUPERUSER*` / `FIRST_OPERATOR_EMAIL` | 不变 | 初始化用，已有数据恢复后不生效 |
| `COST_ALERT_EMAIL` / `PROJECT_NAME` / `COMPOSE_PROJECT_NAME` / `APP_PORT` / `AUDIO_TTL_DAYS` / `ASR_PROVIDER` / `SCORING_PROVIDER` | 不变 | — |

**配套代码改动只有一处**：`compose.yml` 的 `acme` 服务目前吃 `DP_Id/DP_Key`（DNSPod 插件做 DNS-01）。换火山要加火山 DNS 插件的环境变量（AK/SK），并把签发命令的 `--dns dns_dp` 改成 `--dns dns_volc`。这个改动建议在迁移前单独提一个 PR，在老机上用 HTTP-01 兜底验证一次，避免到了新机才发现插件版本不支持。

## 五、执行顺序（四段，时间是硬约束）

### 第 0 段：前置办理（现在就能开始，1-2 周）

1. 确认 `outman.website` 的注册商与到期日 → 规划过户（过户对象＝公司主体）
2. 火山企业账号实名 → 买 ECS（包月）→ 开 TOS 桶（备份异地副本，第七节已拍板）
3. **启动备案**：主体由个人改公司、接入商由腾讯改火山，属「主体变更 + 接入备案」，需向火山备案客服确认同域名已有备案的衔接方式；**旧备案全程保持有效直到新备案通过**
4. 公司火山账号开通方舟模型 → 生成三套新密钥 → 先在本机小流量验证一次 ASR/评分/TTS 是否可用（不要等到切换当天）

> 备案期间老机照常对外服务，用户无感知。

### 第 1 段：新机空跑（备案等待期并行，1 小时）

1. 流水线指向新机全新部署（改 `SERVER_HOST` / `SERVER_SSH_KEY`，约 9 分钟）
2. 只跑结构验证：`/api/v1/utils/health-check` 200、登录页能打开、DB 迁移跑完（空库）
3. 用**新密钥**在新机做一次 ASR/评分/TTS 冒烟（这一步验证的是密钥，不是数据）

### 第 2 段：搬数据（备案通过后，停机窗口内，预计 1-2 小时）

1. 停写：入口暂停作答，等评分任务跑完（不要在评分中停服务）
2. 老机生成一份新备份包：`bash scripts/backup-local.sh` → `bash scripts/verify-backup.sh backups/bundle-...`
3. 搬迁：1.7G 量级，直接 `scp` 或走 TOS 中转，不必拆包
4. 新机恢复：按 [backup-restore.md](backup-restore.md) —— 导入前先建 `esa_app` / `esa_platform` 角色，导入 DB → 展开音频卷 → 起 `db/prestart/backend`
5. **跑恢复演练脚本做验收**（见第六节），不是"看着能登录"就算过

### 第 3 段：切流量（10 分钟操作，观察 1-2 周）

1. 提前 1-2 天把 `outman.website` 的 A 记录 TTL 降到 60s
2. 改 A 记录指向新机 → 观察 backend 就绪、教师/学生登录、课堂列表、历史成绩、录音回放
3. 老机 SpeakUp 容器先 `docker compose down`（**不删数据**），保留 1-2 周做回退保险
4. 回退预案：把 A 记录改回老 IP + `docker compose up -d`，5 分钟内可恢复

### 第 4 段：收尾

1. 老机 SpeakUp 目录与卷在确认稳定后清理（腾 13G）；`outman.website` 的旧证书与旧 cron 一并移除
2. 个人侧：旧备案注销/变更 → 三套个人火山密钥停用 → 域名过户完成
3. 更新本仓库文档：云资源清单里的地址与域名归属

## 六、验收判据（迁移当天必须全过）

用仓库现成的一条命令跑，不靠肉眼：

```bash
# 在新机隔离环境跑：建包 → 独立 Compose 项目 → 39 张表比对 → 音频指纹 → 登录/作答探针
bash scripts/recovery-drill.sh --keep
```

必须同时满足：

- `/api/v1/utils/health-check/` 200，backend/db 容器 healthy
- 39 张表行数与源库一致
- 音频卷「相对路径 + 内容」合并 sha256 一致
- 种子学生能登录、能回放一条作答音频（证明 行 + 受限角色 + RLS + 音频卷 串起来可用）
- 教师端课堂列表、历史成绩可见
- 跨校访问仍被拒（多租户隔离没被迁移破坏）

## 七、备份异地副本桶选型（2026-11-21 已拍板：火山 TOS）

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 阿里云 OSS | 与公司其他业务一个账号一张账单 | 跨厂商，ECS→OSS 走公网，上传 1.7G/天需约十几分钟，且产生出网流量 |
| **火山 TOS（已选）** | 同厂商内网直传，快、几乎不产生公网流量 | 与"对象存储统一用 OSS"的既有决定冲突；本项目备份走 TOS，其他业务仍按 OSS |

**决策（2026-11-21）**：备份副本用 **火山 TOS**——与 ECS/方舟同账号同地域，内网直传省公网出流量、备份链路最短。录音主存仍在服务器本地卷；TOS 只放每日备份异地副本。若后续每日 1.7G 上传成为负担，再把音频改增量备份压体积。
