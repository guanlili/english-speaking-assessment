# 玩法注册表（2026-11-28，#618 第二批）

把「题型」从散落在判分、题面构造、每日挑战映射里的 if/elif 收成一份声明。

## 一、一个玩法声明什么

`backend/app/services/vocab_plugins.py` 的 `PromptPlugin`：

| 字段 | 作用 |
| --- | --- |
| `key` | 稳定标识，与 `VOCAB_PROMPT_TYPES` 对齐（快照、统计、接口都用它） |
| `label_zh` / `label_en` | 学生端玩法名 |
| `dimension` | 能力维度：拼写 / 认读 / 语境 / 词法（每日挑战按维度取不同玩法） |
| `requires` | 素材依赖（词条 / 音频 / 例句 / 词根），降级判断读它 |
| `supports(word)` | 单条词能否出这种题 |
| `payload(idx, word, words, snapshot)` | 快照要固化的题面载荷（选项、挖空句、语素块） |
| `judge(answer, snapshot, key)` | 判分 |
| `renderer` | 前端渲染器标识（现阶段 6 题型共用文本/选择两种） |

## 二、这次改了什么

- 六个既有题型（`meaning` / `audio` / `en_zh` / `zh_en` / `cloze` / `roots`）全部注册，行为**委托原有实现**，所以快照格式、判分结果、统计口径完全不变。
- 学生作答判分改走 `judge_answer(prompt_type, ...)`：未注册题型直接判错，不再静默按拼写比对（以前未知题型会被当拼写题误判对）。
- 快照载荷构造改走注册表的 `payload`：未注册题型不再补选项。
- 每日挑战的维度与候选玩法改为从注册表读取，不再写死「维度 → 题型」映射；新注册玩法自动进入挑战池。
- 注册 key 重复会直接报错，避免两套口径并存。

## 三、新增一个玩法要做什么

1. 在 `vocab_plugins.py` 加一条 `PromptPlugin`，或在独立模块里 `register(...)`；
2. `supports` / `payload` / `judge` 三个函数写清楚，素材依赖填 `requires`；
3. 把 key 加进 `VOCAB_PROMPT_TYPES`（若要对教师暴露）与前端 `PromptBody` 的渲染分支；
4. 补两条测试：`supports` 为 false 时不进题、`judge` 对/错各一例。

不需要改判分入口、题面构造总入口、每日挑战选玩法逻辑——这三处已按注册表分派。

## 四、示例玩法：字母重排 letters

- 注册项 key `letters`，维度 `spelling`，素材只要词条本身
- 可出题条件：纯英文单词、3–14 个字母（太短没意义、太长屏幕上摆不下、短语不参与）
- 题面载荷：按词形稳定打乱字母块，且顺序不等于原词；答题前不下发完整拼写，只给中文释义
- 判分：拼回词形后再按可接受拼写比对（与拼写题同一口径）
- 前端：`PromptBody` 加一个 `letters` 分支（释义 + 字母块 + 提示文案），作答控件沿用文本输入
- 入口：每日挑战（拼写维度候选）与自主练习 `prompt_types=["letters"]` 可用；教师勾选面板下一批接入

## 五、边界

- PK / 摸底测验有各自的快照与判分上下文，暂不接入注册表，避免把「课堂 PK 计分」和「任务判分」两套口径混在一起。
- 注册表现在是进程内声明，不做第三方插件市场、不做热加载、不做计费。
