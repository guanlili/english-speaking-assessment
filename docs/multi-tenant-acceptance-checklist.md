# 第二校上线：AC-01～12 验收证据盘点

**用途**：#223「多租户商用改造」工程主线（A/B/C）已完成，剩余门槛是 **E 期真实第二校试点与最终验收**。本文把 AC-01～12 逐条映射到仓库内现有证据，标出缺口与建议动作，供试点前逐项核对。

**口径与边界**（重要）：

- 本文是**文档层盘点**，不是验收结论。未重新核验生产环境、未新增测试、未代表客户确认任何一项。
- 状态定义：**有证据** = 仓库内存在可复现的证据（测试用例/报告章节/CI 门禁）；**部分** = 覆盖了主要路径但缺少条目中要求的关键子项；**缺口** = 无证据或仅有流程文档。
- 「本地通过」不等于「两校真实环境通过」：现有验证环境是 Mac Mini 本地 docker（单库多租户），第二校的真实账号、数据与网络条件尚未接入。
- 证据文件均随 master 维护，引用路径可直接检索；测试用例以 `backend/tests/` 下文件名与 `def test_...` 名为准。

## 二、缺口与建议动作

按"是否阻塞第二校上线"排序，缺口的处理方式不同：

| 优先级 | 项 | 为什么不补不能上线 | 建议动作 |
| --- | --- | --- | --- |
| P0 | AC-08 公平与容量 | 两校共用一套服务，一校被爆破会拖垮另一校；这是商用化最核心的承诺 | 用现有观测手段做一次两租户混合负载压测，记录 P95 与排队；限流按租户分桶验证 |
| P0 | AC-10 恢复演练（生产数据） | 第二校数据不可恢复的代价无法向客户交代 | 机制已在开发栈跑通（`scripts/recovery-drill.sh`）；仍需在生产主机用真实包跑一次，含录音回放与单校恢复 |
| P1 | AC-07 用量 | 计费基础，错扣会变成商务纠纷 | 补"预占→成功/失败→回滚"与重试幂等用例；供应商侧消耗留对账口径 |
| P1 | AC-05 生产 RLS 核验 | 应用层过滤之外的最后一道防线 | 用生产普通角色账号（非超级用户）跑一次查询，确认缺上下文拒绝 |
| P2 | AC-01/02/04/06/09/11 的子项 | 已有主路径证据，子项属踩实 | 第二校试点时按本表逐条实测，把结果回填到 #223 评论 |
