# 平台角色与权限说明（2026-11 · 四角色版）

> 面向校方与平台运营的权限说明。平台共**四类登录角色**，所有权限均由系统强制执行：
> 看不到的功能不会出现在菜单中，直接输入网址访问也会被拦截；学校之间的数据由数据库层隔离。

## 一、角色总览

| 角色 | 如何登录 | 定位 |
|---|---|---|
| **平台管理员** | 邮箱账号（平台方持有；主登录页或运营入口均可） | 平台方负责人：开校/停校、跨校账号、平台授权词库、全局运行与费用 |
| **学校管理员** | 邮箱账号（平台管理员创建，或本校管理员自建本校教师） | 本校总管：本校教师账号、本校题库结构、本校全部课堂与学生 |
| **教师** | 邮箱账号（学校管理员创建） | 只管自己的课堂：出题、发布、看本班数据 |
| **学生** | 学号 + 密码（教师批量导入建号） | 只看自己的练习记录与成长数据 |

- 每所学校有专属登录链接 `/s/学校码/login`（可直发师生）；主登录页通用。
- 未登录访客无法访问任何页面；**课堂码只能用于学生加入课堂，凭课堂码查看不到任何班级数据**。
- 平台管理员与学校账号是两套独立身份：平台凭证碰不了学校业务，学校凭证碰不了平台管理面（安全设计）。

## 三、关键数据边界（一句话版）

1. **学校之间完全隔离**：每所学校的师生、课堂、题库、成绩互不可见——由数据库层强制（不是"约定"），跨校访问一律按"不存在"处理。
2. **教师之间互不可见**：每位教师只能看到自己负责的课堂与学生的数据；学校管理员可看本校全部。
3. **学生只看自己**：任何情况下看不到同学的数据，也看不到任何管理页面。
4. **平台大盘与账号管理只属于平台管理员**：学校侧无论什么角色都进不去；平台管理员也**看不到学校的教学业务页面**（出题、课堂面板等）——需要时用该校的校级账号。
5. **停用立即生效**：学校被停用后，该校师生立即无法再登录（已登录的会话到期自动失效）；停用不删除任何数据。
6. **权限由系统强制**：以上边界是平台内置的访问控制，不依赖使用者的自觉。
