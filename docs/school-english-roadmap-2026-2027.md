# Charcoal 校级英语提分需求池与迭代建议

整理日期：2026-10-21。状态：需求讨论稿，未承诺开发时间。

依据：2026-10-20《English Results and AI: Proposed Course of Action》8 页双语草案，以及仓库当前模块文档。本文把方案转为产品建议；原方案中的审批、采购、人员分工与汇报安排不视为已获授权的执行任务。现有能力判断基于仓库文档与部分数据结构核对，未进行生产环境验收。

## 1. 产品方向

建议从“教师主导的口语、词汇课堂工具”，逐步扩展为“支撑校级英语提分的教学与数据平台”。保留教师主导，补齐以下链路：

学生档案 → 外部测评与基线 → 教师确认分组 → 统一教学计划 → 每日分层任务 → 练习与补练 → 阶段复测 → 校级汇报 → 调整教学与分组。

首阶段覆盖高中；初中作为后续扩展。平台承担记录、教学执行与分析，测评机构提供正式测评，学校负责目标确认、师资、排课与教材。

## 2. 已有基础与实际缺口

| 领域 | 当前基础 | 本次增量 |
| --- | --- | --- |

| 词汇 | 五级词库、任务、测验、错词复习、AI讲解与学情 | 与周教学计划联动、间隔复习与掌握度 |
| 模考 | 口语模考、自动考试、计时、回看 | 外部模考成绩归档与检查点；不能据此宣称已有全科官方模考 |
| 题库与备课 | 导入导出、AI出题草稿、复制、发布快照、全校可见与作者编辑保护 | 教研课程包、审核与版本、跨教师协作 |
| 学情报告 | 课堂结果、个人成长、7/30/90天阶段报告、录音开口时长 | 跨课堂去重、年级/全校月报、官方成绩与目标追踪 |
| 组织管理 | 学号账号、课堂、教师归属、名单 | 稳定校级学籍、行政班与教学组并存、跨部门权限 |

| 运维 | 部署、监控、本地完整备份与恢复流程 | 学校托管/移交、异地备份、容量与成本测算 |

以上以当前模块说明为准；教师设计文档中较早的“题库复制未实现”描述，已被后续实现记录覆盖。

## 3. 需求池

优先级：P0 为基线与可信汇报的前置条件；P1 为教学落地与主要能力补齐；P2 为效果优化。以下均为建议优先级，进入排期前需确认范围与资源。

| ID | 优先级 / 性质 | 需求与最小范围 | 首版验收标准 | 依据 |
| --- | --- | --- | --- | --- |
| R01 | P0 / 增强 | **统一学生档案**：稳定学生标识、年级、行政班、在籍状态、考试方向；导入预览、重复与离校档案核对 | 同一学生跨课堂只计一人；缺测、离校、待核对名单可分别导出 | 方案第1–3页：覆盖缺口与档案清理 |
| R02 | P0 / 新增 | **外部成绩档案**：记录Aptis、TOEFL、IELTS及历史其他考试的原始成绩、分项、考试日期、考试版本/量尺、来源、凭证、核验状态和修订记录 | 官方成绩、机构模考、平台参考分分开展示；不同考试量尺不能录混；修订有据可查 | 第2–3页：统一成绩档案 |
| R03 | P0 / 新增 | **成绩更新与核验**：支持导入/人工录入、待核验队列、退回、确认、缺凭证提醒；先明确录入人与最终核验人，再配置流程 | 未核验成绩不进入官方达标统计；可查谁在何时核验；支持双月更新名单 | 第2页：班主任→年级→教务→外语部的草案备注；流程仍待确认 |
| R04 | P0 / 新增 | **基线与检查点管理**：登记测评批次、应测名单、缺考/补测、基线与复测对应关系；首版管理外部测评结果 | 高一高二可看基线、3月、6月记录；高三可单独走官方成绩与方向模考；缺测不当作0分 | 第2–3、5页：测评周期与年级差异 |
| R05 | P0 / 增强 | **校级权限与审计**：按学校确认的职责配置教务核验、年级汇总、教研管理、管理层查看权限；保留教师课堂边界 | 教师不会因跨班汇总而获得全校原始录音权限；成绩凭证与导出可追踪 | 第5、7页：角色分工与数据治理 |
| R06 | P0 / 增强 | **可信周报与月报基础版**：按年级汇总参与、任务完成、录音时长、外部测评覆盖率与已核验达标率；固定周期导出一页报告 | 所有比例附人数和分母；可追溯明细；官方成绩与练习反馈独立；能输出首份月报 | 第4页：每月一页报告 |
| R07 | P1 / 新增 | **行政班与教学组并存**：年级内按教学层级与TOEFL/IELTS方向建立组；教师确认分组与调整生效日期 | 早读仍归行政班、晚课归教学组；换组不搬走旧记录；全校统计不重复计数 | 第3–4页：按层级和方向分组 |
| R08 | P1 / 增强 | **同班差异化任务**：老师对组/指定名单发布不同难度的口语、词汇任务；统一“今日任务”入口与来源标识 | 同班不同学生看到各自题单；教师预览每组接收人；发布与历史快照不漂移 | 第4页：早读同班分层练习 |
| R09 | P1 / 增强 | **16周教学计划与早读模板**：按层级/方向维护周目标、材料、词汇与任务包；早读支持“词汇热身→引导口语→录音” | 教研组制作一周内容后，多位教师能预览、复制并发布；学校提供并审核教学内容 | 第4页：统一进度与固定流程 |
| R10 | P1 / 增强 | **教研共享内容包**：在已有题库复制与保护基础上增加课程包、负责人、草稿/审核/发布状态、版本及授权来源 | 教师复用内容包不会覆盖原作者内容；版本可追溯；历史练习仍按原快照展示 | 第4、7页：共建材料与教师工作量 |
| R11 | P1 / 新增 | **阅读理解MVP**：授权文章、单选/判断/匹配等客观题、确定性判分、答案解析、错题、教师结果；先选少量题型完成闭环 | 能完成“导入文章和题目→发布→阅读作答→结果分析”；阅读正确率与朗读参考分分开 | 第2、4页：阅读为主要短板，模块可行性待评估 |
| R12 | P1 / 增强 | **目标与干预追踪**：在基线人群上设置阶段目标，记录教师干预、补练、复测和后续分组建议 | 可追踪起点A1/A2人群的复测；分项量表分变化与等级变化并列；目标确认后才启用达标规则 | 第3页：薄弱生与量表分进步 |
| R13 | P1 / 新增 | **出勤与异常归因**：先做人工出勤/请假/缺考记录，并区分未参与、技术故障、评分失败、未完成 | 未提交不自动等于缺勤；报告能按出勤与缺测解释成绩覆盖 | 第7页：低出勤影响数据 |
| R14 | P1 / 增强 | **AI评分抽样复核**：复用现有教师复核入口，增加学期抽样计划、评分标准版本、人工独立评分、偏差统计与后续处理 | AI与教师评分独立保存；只在可比口径下统计偏差；不回写官方成绩 | 第7页：每学期抽样对比 |
| R15 | P0评估 / 分步落地 | **学校托管、数据移交与容量成本**：托管/数据归属清单、录音保留与访问策略、异地备份和恢复演练、学校接管说明；测算评分/TTS/存储费用与峰值 | 明确接管责任与恢复步骤；全校推广前验证实际高峰；提供按使用情景测算的月成本 | 第6–8页：运行费用与托管归属 |
| R16 | P2 / 增强 | **个性化复习与技能扩展**：词汇间隔复习、跨任务掌握度；阅读后再评估听力、语法、写作 | 复习能追溯真实作答；教师任务优先；新增技能各自有内容负责人和验收目标 | 方案第4页基础层重点；间隔复习及技能扩展为产品推导 |

R06先做基础汇总，R12再补目标人群与干预效果分析；R15的学校责任、访问与恢复底线应在全校推广前明确，完整治理能力可以分批交付。

## 4. 必须提前统一的数据口径

1. **原始成绩优先**：保留考试名称、版本、量尺和分项。跨考试对照如确有需要，单独保存规则与依据，经校方确认；不得用AI参考分自动推断正式Aptis、TOEFL或IELTS成绩。
2. **分开计算不同目标**：高一高二的Aptis成长、高三的正式考试达标率分别统计。同一学生满足多个考试门槛只计一次；采用最新成绩还是某时段内最好成绩、有效日期如何定，需先确认。
3. **覆盖率和达标率同时披露**：全体在籍口径、已核验有成绩口径、目标基线人群口径分别列人数；缺测不算0分，也不能悄悄从分母移除。历史月报保留当期名单与规则。
4. **时间含义准确**：当前累计录音时长可称“开口时长”，不能直接称为全部学习时长。词汇/阅读有效练习时长需新增采集与去空闲、跨窗口去重规则；首版可先只报告可验证的时长与完成量。
5. **趋势须可比**：口语题型、难度、评分引擎变化可能影响分数。保留题型与引擎维度；“练习分上涨”只表述为练习表现变化，不能据此断言正式成绩提升由平台造成。
6. **两类分级分开**：KET/PET等内容标签、五级词库、外部CEFR能力等级、学校教学组是不同概念，不能相互直接代替。

## 5. 建议迭代顺序

下表为配合方案的目标窗口，不是工期承诺；每批范围需单独估算。

| 批次 | 建议窗口 | 主要需求 | 交付结果 |
| --- | --- | --- | --- |
| A：建立可信基线 | 2026年10月底至11月中优先启动 | R01–R05、R15评估 | 干净学生名册、成绩导入核验、基线与缺测名单、数据责任边界 |
| B：形成首份汇报 | 2026年11月至12月 | R06、R13最小范围、R15必要落实 | 可解释的年级汇总、参与与缺测数据、一页月报 |
| C：落实分层教学 | 2026年12月至2027年1月 | R07–R10；R11先试点一组 | 同班不同任务、晚课教学组、周课程包、阅读闭环试点 |
| D：支持3月检查点 | 2027年3月初前 | R12、R14、R11试点后扩展 | 基线复测对比、薄弱生目标追踪、调组建议、评分复核 |
| E：优化与扩围 | 2027年3月至6月 | R16、学年汇总、初中需求评估 | 复习优化、学年报告与下一阶段范围 |

资源紧张时，先保A、B以及C中的教师手动分组和差异化发布。阅读理解保留高优先级，但先验证MVP；若暂不可开发，可先在线下使用分级阅读材料，平台登记任务与结果，明确标注线下来源，不伪装为在线阅读行为。

## 6. 阅读模块首版边界

建议围绕基础层和提升层试点，复用账号、课堂、发布快照与结果入口，新增独立的阅读理解内容、作答与判分能力。避免把现有文章朗读评分改造成阅读理解评分。

首版包含：文章与题目导入、客观题、教师审核解析、限时可选、逐题对错、教师完成/正确率、少量经教研确认的技能标签（如主旨、细节、推断）。暂缓完整托福/雅思阅读仿真、开放题AI判分、自适应能力测试、自动生成正式分数。平台开发完成之外，需安排教研人员提供授权材料、答案和解析。

## 7. 排期前需要校方确认的事项

- **定位调整**：是否正式把校级成绩与分层教学纳入平台？当前规则是教师选题、全班同题，CEFR仅作内部元数据且不向学生展示。新增教师可见的分组与学生差异化任务，需要更新产品规则；建议学生仍直接看任务，不展示固定能力标签，不按AI分自动调组。
- **目标定义**：“大多数薄弱生”具体比例是多少？是否采纳Aptis总体B1？量表分提升是否设门槛？正式考试成绩使用哪一时间口径？这些是方案待决项，不能写死为已批准目标。
- **人数核对**：方案总人数359，但年级84+133+143=360；高一65/84与补测24人不一致；阅读样本59人与基线65人可能为不同有效样本；预算中的高一高二216人与年级合计217人也不同。统一名册后再生成测评覆盖与预算。
- **检查点起点**：11月中至12月初完成基线，到3月初并不对每人都满4个月。应确认统一日历检查点，还是逐人从基线起计算；系统保留真实日期。
- **组织流程**：明确谁录入、谁核验、谁可查看凭证、谁批准调组，以及双月成绩更新流程是否采纳。先支持实际必需步骤，避免把草案备注直接做成多级审批。
- **校方投入**：明确16周教材、阅读题目与版权、测评供应商结果样例、数据归属与托管负责人。考试采购与排课不作为平台开发完成的替代物。

## 8. 暂不优先投入

全科官方考试仿真引擎、AI自动分班、复杂自动排课、向学生展示固定CEFR标签、无法核实的跨考试换分、公开排名，以及学校尚未确认的多级审批。听力、语法、写作进入后续需求池，待阅读试点与教师内容供给验证后排期。
