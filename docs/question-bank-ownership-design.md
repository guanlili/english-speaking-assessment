# 题库归属分层设计（个人 / 校内共享）

> 状态：设计稿（2026-10-16），待确认「待决问题」后实施。背景见 `docs/teacher-platform-design.md`「未排期需求：题目库区分个人和校内共享、复用他人内容默认复制」。

## 1. 现状与问题

- 四类题库根对象（`Passage`、独立 `RepeatSentence`、`Scenario`、`Instruction`）都没有归属字段；`admin_content.py` 约 40 个读写/删除接口统一用 `TeacherUserDep`——**任何教师都能编辑、物理删除全校任何题目**。
- 发布快照保证了已发布练习与历史成绩不受影响，但以下场景仍会互相干扰：
  - B 老师改了 A 老师的篇目正文或标准音，A 老师下次组卷拿到的是改过的内容；
  - B 老师删掉题目，A 老师的组卷草稿（`ComposerDraft.state` 按 ID 引用）恢复时变成「缺失」；
  - 题库导入查重是全局口径：A 老师导入的题会被判定与 B 老师的题重复。
- 教师数增长后，题库列表也会越来越难找到"自己的题"。

## 2. 目标与非目标

目标：

1. 每位教师有自己的题目（默认只有自己可见、可改）。
2. 教师可把自己的题共享到校内；其他教师可以选用，但**不能直接改别人的题**，要改就「复制到我的题库」。
3. 现有题目、发布快照、历史成绩、草稿行为不漂移。

非目标：跨学校隔离（多租户）、审批流、协同编辑、版本历史。

## 3. 数据模型

在四类根对象上新增两列（子对象继承根对象，不单独建列）：

| 列 | 类型 | 说明 |
|---|---|---|
| `owner_id` | `uuid` 可空，FK `user.id`，`ondelete=SET NULL`，索引 | 创建者。NULL = 存量/无主内容 |
| `visibility` | `str(16)`，`private` / `school`，`server_default='school'`，索引 | 可见范围 |

- 根对象：`Passage`（`parent_passage_id IS NULL` 的整篇；旧版子篇继承父篇）、独立 `RepeatSentence`（`passage_id IS NULL`）、`Scenario`、`Instruction`。
- 子对象：挂篇目的 `RepeatSentence`、`ScenarioQuestion`、旧版子篇——权限一律按根对象判定。
- `Unit`（单元/主题树）与 `SentenceFrame`（句型库）保持管理员维护的全校公共数据，不加归属。
- 迁移：存量行 `owner_id=NULL, visibility='school'`——对所有教师的可见性与今天完全一致。

### 必须同步调整的唯一约束

- `Scenario.topic` 目前全局 `unique`：两位老师各建一个私有的「Pets」主题会冲突。改为部分唯一索引：`visibility='school'` 时 `topic` 唯一；私有主题按 `(owner_id, topic)` 唯一。
- `Passage.slug` 全局唯一保持不变（创建时已自动 `-2/-3` 去重，复制时同样走去重）。

## 4. 权限矩阵

| 操作 | 自己的（任意可见性） | 他人 `school` | 他人 `private` | 存量（owner NULL） |
|---|---|---|---|---|
| 列表/详情/组卷选用 | ✅ | ✅ | ❌（404，不暴露存在） | ✅ |
| 编辑/换标准音/拆句/考试设置 | ✅ | ❌ → 提示「复制到我的题库」 | ❌ | 见待决问题 Q2 |
| 删除 | ✅ | ❌ | ❌ | 见待决问题 Q2 |
| 共享到校内 / 取消共享 | ✅ | — | — | 仅管理员 |
| 复制到我的题库 | ✅ | ✅ | ❌ | ✅ |

管理员（`is_superuser`）全部放行。实现上抽一个 `services/content_access.py`：`visible_filter(user)`（返回 SQL where 子句，列表与查重共用）+ `require_editable(session, user, root)`（编辑/删除入口统一调用），路由只做调用，不再各写一遍。

## 5. 各链路改动

- **创建**：落 `owner_id=current_user.id`，`visibility` 默认值见 Q1。
- **列表与组卷分页**：所有列表接口加 `visible_filter`；新增可选 `scope=mine|school|all` 筛选（默认 all）。前端题库页与组卷面板加「我的 / 校内」切换，条目显示「我的 / 某老师共享 / 公共」徽标。
- **发布校验**：`PUT /classes/{code}/assignment` 与草稿保存时逐项校验 item 对发布者可见，不可见按「题目不存在」处理——防止猜 ID 发布他人私有题。已有快照不受影响。
- **组卷选择恢复**（`POST /admin/composer-selection`）：不可见 ID 归入现有的「缺失」分支，界面已有处理。
- **取消共享 / 删除**：只影响他人后续组卷；他人草稿里的引用落入「缺失」，已发布快照与成绩不变（沿用现有不变量）。
- **复制**：`POST /admin/{kind}/{id}/copy` 深拷贝根对象与子对象（篇目连同复述句、主题连同全部问法），新对象 `owner=当前用户, visibility=private`，记录 `copied_from_id`（可选列，用于界面显示"复制自"）。标准音 URL 直接沿用：内容音频目前没有任何删除路径，共享文件安全；以后如果加音频清理，需要先改成引用计数。
- **导入查重**（`services/question_bank_io.py` `_matching_ids` 等）：候选集合改为 `visible_filter` 范围，否则会把别人的私有题当成重复、或泄露其存在。导入新建的内容归导入人。
- **导出**：仅导出可见内容。
- **AI 出题 / 自动拆句**：沿用编辑权限。

## 6. 分期

1. **P1 归属与保护**：迁移两列 + 创建落 owner + 编辑/删除守卫 + 列表可见性过滤 + 「我的/校内」筛选 + 发布可见性校验 + 导入查重口径。这一期就解决"别人改/删我的题"。
2. **P2 复制**：复制接口与「复制到我的题库」入口；他人题目的编辑按钮替换为复制。
3. **P3 共享管理**：共享/取消共享开关、「复制自」溯源展示、按老师筛选。

每期都要：后端测试覆盖权限矩阵每一格；E2E 覆盖两位老师互相不可改；中英双语文案；390/820/1180 三档宽度检查。

### P1 已实施（2026-10-16，迁移 `a7d3e9f1c205`）

只做"编辑保护"，暂不加 `visibility` 列（等同 Q1 选 `school`：所有题目对全体教师可见、可组卷）。实际口径：

- 四类题库表加 `owner_id`（FK user，SET NULL）。教师新建落本人；**管理员新建为 NULL**（学校公共素材，教师可改）。
- 可改条件：管理员 ‖ `owner_id` 为空 ‖ 本人（`app/services/content_access.py`，403 文案「没有权限：只能修改自己创建的题目」）。Q2 暂按 **A**（存量仍可改），切到 B 只需改 `can_edit`。
- 挂篇目的复述句继承篇目归属（篇目的旧版拆分子篇看父篇）；不能把句子移到/添加到他人篇目。
- 情景主题是共用分组：任何教师可往主题里加题；改名/启停/删除主题需组内题目都可改。
- **考试流程设置不设守卫**：组卷时要能给他人题目调计时。AI 出题只出草稿，也不设守卫。
- 导入：新行归导入者；复述句挂到他人已有篇目时整批 403（预览阶段暂不提示）。
- 前端 `useCanEditContent` 隐藏他人题目的编辑/标准音/删除按钮，显示「其他老师创建 · 只读」；考试设置按钮保留。测试 `test_content_ownership.py`。

## 7. 待决问题（需要产品确认）

- **Q1 新建内容默认可见性**：`private`（隔离彻底，但老师要记得共享才能被同事用）还是 `school`（延续今天的协作习惯，只是加了编辑保护）？建议 `school`——改动对老师感知最小，同时已解决互相改题的问题。
- **Q2 存量内容（owner 为空）谁能改**：A. 仍允许所有教师编辑（行为不变，但保护不覆盖存量）；B. 仅管理员可改，教师要改就复制；C. 迁移时按 `created_at` 附近的操作日志认领——没有可靠数据源，不建议。建议 B，并提供管理员批量「指定归属」工具。
- **Q3 管理员是否能看到教师的私有题**：建议能（便于运维与离职交接），界面标注「私有」。
- **Q4 教师离职**：`owner_id` 为 SET NULL，内容转为无主存量；是否需要「转交给某老师」工具？
