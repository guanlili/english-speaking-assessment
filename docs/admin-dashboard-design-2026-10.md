# 管理员平台大盘设计（Admin Dashboard）

日期：2026-10-23 ｜ 状态：设计稿，待评审
作者背景：教师端已有"单课堂大盘"（面板统计卡 + 名单 + 班级趋势 + 弱项 + 实时状态）。本设计把同一心智模型放大到全平台：**管理员看平台，如同教师看课堂**。

---

## 1. 目标与非目标

**目标**
- 管理员（校方/运营）一页回答四类问题：
  1. 平台**今天/近期用得怎么样**（业务）；
  2. 系统**现在健康吗**（性能与稳定）；
  3. **花了多少钱**（费用）；
  4. **资产有多少**（内容/账号/存储）。
- 出问题时不用 SSH 上服务器翻数据（现状：`/admin/metrics` 只有裸 JSON，无历史）。
- 所有口径与教师端一致（同一张 attempt/practice_session 表算出来的数，不允许两套口径）。

**非目标（明确不做）**
- 不做 Prometheus/Grafana 接入（现指标端点设计哲学就是"无采集端、JSON 直读"，维持）；
- 不做实时秒级监控（教学场景分钟级足够，评分队列状态 30s 轮询即可，沿用 `pollWhileVisible`）；
- 不做自动云账单拉取（火山账单 API 需主账号凭证 + T+1，v1 用"平台自估 + 手工对账"）；
- 不给教师角色开放费用与性能区（教师只看得到内容管理四页，权限模型不变）。

## 2. 用户与场景

| 用户 | 场景 | 高频动作 |
|---|---|---|
| 校方管理员 | 周例会/月报：汇报平台使用情况 | 看"业务大盘"选时间范围，导出 CSV |
| 校方管理员 | 老师反馈"平台卡/评不出分" | 看"性能与稳定"区队列与失败率 |
| 运营（我方） | 月度成本核算、容量规划 | 看"费用大盘"，与云账单对账 |
| 运营（我方） | 推广判断：哪些班在用/沉默 | 看"课堂使用排行"与"沉默班级" |

## 3. 信息架构（单页四区 + 顶部速览）

路由 `GET /admin/dashboard`（前端 `/admin/dashboard`，仅 superuser；admin 布局导航加"平台大盘"入口）。桌面四区纵排，390/820/1180 三档自适应（卡片区自动折行，趋势图横向滚动）。

```
┌────────────────────────────────────────────────────────────┐
│ 平台大盘          [今日|7天|30天|90天|全部]  ⟳刷新  ⤓导出CSV │
├────────────────────────────────────────────────────────────┤
│ ① 今日速览（stat 卡 ×6，随全局时间范围联动为区间值）          │
│  [活跃学生] [活跃课堂] [新增作答] [评分成功率] [模考场次] [待处理异常] │
├───────────────────────────────┬────────────────────────────┤
│ ② 业务大盘                     │ ③ 性能与稳定（实时，30s轮询） │
│  · 日活趋势（学生/课堂双线）      │  · 评分队列：各状态数+最老排队 │
│  · 作答量趋势（按题型堆叠）       │  · worker 存活/配置          │
│  · 平均分趋势（问答/跟读分线）    │  · ASR/LLM/TTS 失败率+延迟    │
│  · 题型分布（占比条）            │  · 数据库连接池水位条          │
│  · 课堂使用排行（表：班/生/答/分） │  · 运行异常上报数（按类型）     │
│  · 沉默班级提示（n 天零作答）      │  · 音频存储：体积/文件数/孤儿   │
├───────────────────────────────┴────────────────────────────┤
│ ④ 费用大盘                                                   │
│  [本月 AI 估算] [本月服务器] [单位成本/作答] [趋势条形×6月]      │
│  分项：ASR(音频小时) / LLM(调用×token) / TTS(字符) ＋ 实际账单对账栏 │
├────────────────────────────────────────────────────────────┤
│ ⑤ 资产与账号（次屏，卡片×4）                                   │
│  题库(题型×n) / 词库(书×词) / 账号(师/生/待改密) / 发布次数       │
└────────────────────────────────────────────────────────────┘
```

明细下钻：课堂排行行 → 弹窗该班"学生汇总"表（即 2026-10-23 导出的学生汇总口径，按课堂过滤）；每区右上角"导出 CSV"复用导出查询。**大盘页本身不承载逐题明细**——明细保持在教师端与导出，避免权限模型复杂化。

## 4. 指标字典

### ① 今日速览 / 区间速览
| 指标 | 口径 | 来源 |
|---|---|---|
| 活跃学生 | 区间内 attempt.student_id 去重（无学生记录不计） | attempt |
| 活跃课堂 | 区间内有会话的 classroom 去重 | practice_session |
| 新增作答 | 区间 attempt 行数（含失败） | attempt |
| 评分成功率 | done / (done+failed)（排除在途） | attempt.status |
| 模考场次 | 区间 exam_started_at 非空会话数 | practice_session |
| 待处理异常 | runtime_issue 非空会话数 + 评分 failed 未重试成功数 | 两表 |

### ② 业务大盘
| 指标 | 口径 |
|---|---|
| 日活趋势 | 按日 distinct student（有作答）；同图叠课堂线 |
| 作答量趋势 | 按日 count(attempt)，分 passage/repeat/question 三色 |
| 平均分趋势 | 按日 avg(overall) where status=done，问答与跟读分线（对齐教师端"班级趋势"口径：未终结考试轮不计） |
| 题型分布 | 区间 count by item_type |
| 课堂排行 | 每课堂：学生数/作答数/平均分/最近活跃；默认按作答数降序 |
| 沉默班级 | 活跃课堂中"最近 N 天（默认14）零作答"列表，提示管理员推动 |

### ③ 性能与稳定（全部来自现有 `/admin/metrics`，首次在 UI 呈现）
评分队列 by_status / 最老排队年龄（>5min 标黄，>25min 标红，阈值取自 QUEUED_STALE_TIMEOUT_S 语义）；worker 配置与存活；ASR/LLM(by kind)/TTS 调用数、失败率、均延迟；DB 连接池 checked_out/(pool+overflow) 水位条；runtime_issue 按类型计数（业务侧可见的"学生端出问题了"）；音频存储 total_bytes/file_count + 孤儿文件数（文件不在 attempt.audio_path 集合，60s 缓存已有，补孤儿维度）。
注意：进程内计数器重启归零——UI 显示"自进程启动"标签；历史趋势依赖 ⑥ 的日快照。

### ④ 费用大盘（估算口径，页首明示"估算，实际以云账单为准"）
| 分项 | 计算式 | 单价（配置常量，来自 docs/pricing-assessment-2026-10.md） |
|---|---|---|
| ASR | sum(attempt.duration_s) 当月 → 小时 × 单价 | ¥4.5/小时 |
| LLM | 问答题 done 作答数 × 单次估token（600进+600出）＋ 词汇AI缓存未命中数 × 估token；P2 换真实 usage | ¥0.6/M进 + ¥3.6/M出 |
| TTS | 内容音频生成字符数（content/ 目录按文件记账，一次性成本） | ¥5/万字符 |
| 服务器 | 固定 ¥185/月（手工配置项） | — |
派生指标：每作答单位成本 = AI 总估算/作答数；每人月成本。月度趋势（近 6 月条形）。对账栏：管理员手工录入当月实际账单金额，存 config 型小表，页面显示 估算vs实际 偏差%。

### ⑤ 资产与账号
题库各题型条数（含单元分布）、词库书×词条、账号数 by role + must_change_password 待改密学生数、累计发布次数与模考发布数、音频存储体积（同③）。

## 5. API 设计（后端，全部 SuperUserDep、只读）

```
GET /admin/dashboard/overview?days=7|30|90|all   → 速览卡 + 区间汇总
GET /admin/dashboard/usage?days=…                → 趋势序列 + 分布 + 课堂排行 + 沉默班级
GET /admin/dashboard/content                     → 题库/词库/账号/发布 资产计数
GET /admin/dashboard/cost?month=YYYY-MM          → 分项估算 + 近6月 + 对账记录
GET /admin/metrics（已有）                        → ③区直接复用，不动
```
- 聚合查询全部走既有索引（attempt: ix_status_created_at、session: session_date/classroom_id/student_id）；课堂排行单查 group by classroom。
- 响应缓存 60s（对齐 metrics.py 音频缓存模式）；趋势图数据按日预聚合在 SQL 内完成。
- 前端：TanStack queryKey ["admin","dashboard",section,range]；③区 `pollWhileVisible` 30s。
- CSV 导出：复用 2026-10-23 导出 SQL 的服务端实现（作答明细/练习轮次/学生汇总三口径 + 时间范围过滤），管理员页可直接拉全量。

## 6. 数据与采集：唯一新增表

`admin_metrics_daily`（日快照，让"性能/费用"有历史、重启不丢）：

| 列 | 说明 |
|---|---|
| date (unique) | 快照日 |
| attempts_done/failed、active_students、sessions | 业务日量（也可从明细表反算，存快照为省聚合） |
| asr_seconds、llm_calls_by_kind (jsonb)、tts_chars | 计费用量基数 |
| llm_tokens_in/out (可空) | P2 真实记账后填 |
| queue_max_age_s、pool_max_checked_out、failure_counts (jsonb) | 当日峰值（由进程计数器每分钟滚动记录峰值，落日写库） |
| est_cost_cny (jsonb 分项) | 当日估算费用 |

写入方式：后端常驻线程（复用 scoring worker 的线程模式）维护"当日峰值"，每日 00:05 落一行；无外部 cron 依赖。历史回填：业务量从明细表回算补齐，运行时峰值无历史则空。

## 7. 权限、文案与自适应

- 仅 superuser（403 不登出语义不变）；`/admin/dashboard` 加入 admin 布局导航，教师不可见。
- 全部用户可见文案中英双语 `useI18n().t({zh,en})`；指标名与教师端术语统一（terms.ts 单一事实源，新增 EXPLAIN 条目沿用"触碰给解释"：每个指标卡 InfoHint 一句话口径说明——用户易用性主张）。
- 三档宽度：390 单列卡纵排、820 双列、1180 完整布局；图表触控目标≥44px；表格在 390 降级为关键列。
- 图表不引第三方库：趋势复用 TrailChart（已有 SVG 实现），分布/费用条形用 CSS 宽度条。

## 8. 分期实施

| 期 | 内容 | 工作量估 |
|---|---|---|
| **P0（建议先做）** | ①②⑤区 + overview/usage/content 三接口 + 页面与导航 + 指标 InfoHint + e2e 冒烟 | 后端 1 天 + 前端 1.5 天 + 测试 0.5 天 |
| **P1** | ③区 UI 化（复用 metrics 接口）+ admin_metrics_daily 表与写入线程 + 费用④估算版 + 对账录入 | 2 天 |
| **P2** | ARK 响应真实 token 记账（scoring 链路回填 usage）、队列年龄阈值告警（面板红点/邮件）、明细 CSV 导出入口、（可选）账单 API 拉取 | 按需 1–2 天 |

依赖与风险：
- 费用估算口径需与校方沟通确认"估算展示"可接受（涉及钱，页首必须挂"以云账单为准"声明）；
- attempt 表量级增长后按日聚合需关注（当前 2k 行无压力；>50 万行时加生成列 date + 索引）；
- admin_metrics_daily 写入线程要接进现有优雅退出（worker 模式），避免重复落行（date 唯一约束幂等）。

## 9. 待拍板的三个选择

1. **费用口径**：v1 估算展示（快、零凭证）即可，还是要等 P2 真实 token/账单 API？（建议：先估算，页首声明）
2. **沉默班级阈值**：默认 14 天零作报提示，是否合适？（建议：14 天，可配）
3. **课堂排行下钻**：v1 只到"该班学生汇总弹窗"，还是要链接进教师视角的课堂面板（管理员代看班级大盘）？（建议：弹窗即可，代看属权限模型变更另议）
